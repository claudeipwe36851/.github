<p>把「住宅 IP 服务器」当成一台普通机器去比 CPU、内存、带宽，最后一定会陷进参数表：两家报价差一倍，配置看着差不多，用起来一个能扛住晚高峰、一个每天掉三次。这类产品的差异不在单机配置，而在四层结构的组合——接入层决定出口能不能用，承载层决定扛不扛得住并发，管理层决定你要搭多少人力，保障层决定出事之后多久能恢复。三层拆开评，才有可比性。</p>

<h2>一、把选型拆成四层，先看清钱花在哪一层</h2>
<p>四层的成本占比并不平均，还会随规模变化。规模小时钱主要花在接入层，因为出口本身稀缺；规模上去之后，承载层和管理层的占比会明显上升。先判断自己处在哪个阶段，再决定预算压在哪一层，比逐项比价有效得多。</p>

<h2>二、接入层：出口类型决定可用性的上限</h2>
<p>同样标着「住宅」，双 ISP、单一 ISP、家庭宽带、机房伪装四种在识别层面的表现差别很大。判断依据不是商品名，而是 ASN 与路由：ASN 归属运营商、段内带有家庭特征地址的，通常更接近真实家宽；ASN 属于云厂商或小型转售商的，即便写着住宅也要多问一句。</p>
<h3>用 ASN 和路由做交叉验证</h3>
<p>拿到地址后做三件事：查 ASN 归属，看该 ASN 下是否同时挂着大量已知代理段，用 traceroute 看最后一跳落在运营商骨干还是数据中心。三项里有两项异常，基本可以判定为转售或伪装。这些查询都免费，十分钟能做完，比试用三天更省时间。</p>

<h2>三、承载层：带宽和并发是两个独立瓶颈</h2>
<p>带宽不够表现为传输慢，并发不够表现为排队等待，两者现象不同，解法也不同。很多人把「卡」都归因于带宽，加钱升档之后排队依旧。判断方法很简单：单次请求里首字节时间正常但下载阶段长，是带宽问题；连接建立阶段就等待，是并发或端口不足。</p>
<h3>带宽估算：先算清单请求体积</h3>
<p>对话类业务的单次请求通常在几十 KB 到几百 KB，含图片或文件上传的会到几 MB。用日请求量乘以单请求体积，再除以业务集中时段的小时数，得到峰值带宽下限，留一倍余量就是该选的档位。</p>

<h2>四、管理层：面板和日志决定长期人力成本</h2>
<p>这一层最不容易被写进比价表，却最影响日常。能在控制台一次改十条线路，和必须逐台登录改，长期差的是一整个人的工时。评估时看三件事：能不能批量改配置、能不能按账号查历史请求、有没有可供程序调用的接口。</p>
<h3>日志至少要留这几个字段</h3>
<p>时间、账号标识、出口地址、目标域名、状态码、耗时、重试次数。少一个都会在排障时卡住：没有出口地址判断不了是否串线，没有重试次数分不清是网络差还是代码在放大失败。字段不必多，但这七项建议固定下来。</p>

<h2>五、保障层：替换政策和响应时间要落到条款</h2>
<p>「有问题随时换」是口头承诺，「每月可免费替换两条、提交后 4 小时内处理」才是可执行条款。评估时把两者的差别问清楚：替换免费还是折价、有没有次数上限、替换后原地址保留多久、非工作时间响应时效是否一致。</p>
<h3>口头承诺怎么变成可执行条款</h3>
<p>签之前把四个问题写进邮件或合同附件：替换触发条件（连续多久不可用）、处理时限（工作日与非工作日分别多久）、费用由谁承担、争议时以谁的监测数据为准。四条写清楚，后面少吵很多架。</p>

<h2>常见问答</h2>
<h3>带宽买大了会浪费吗？</h3>
<p>答：会。带宽属固定成本，闲置部分不退。建议按第九十五百分位的实际用量选档，观察一个月再调整，不要按峰值一次买满。</p>
<h3>并发档位和端口数是同一个东西吗？</h3>
<p>答：不是。端口是接入入口的数量，并发是同时保持的连接上限。一个端口可以承载多条连接，倍数由服务商实现决定，采购时要分别确认。</p>
<h3>地区覆盖越多越好吗？</h3>
<p>答：不一定。覆盖广往往意味着资源分散，单地区深度可能不足。业务集中在两三个地区时，优先看这几个地区的段内质量和替换储备，而不是总覆盖国家数。</p>
<h3>没有技术团队能自己评估吗？</h3>
<p>答：可以做基础评估。ASN 查询、延迟测试、丢包统计都有现成工具，按上面的顺序做一遍能筛掉大部分不合格选项，复杂的并发压测再考虑借助外部。</p>
